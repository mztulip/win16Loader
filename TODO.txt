ETAP 10 - Pelna aplikacja Win16 + pelnoekranowy TextOut           [TODO]
--------------------------------------------------------------------------
Cel: "Hello, Win16!" widoczne w dowolnym miejscu ekranu graficznego 640x480.

Problem: TextOut w GDI.EXE ograniczony do y<20 (pierwsze 64KB LFB).
  640*480*3 = 921600 B > 65535 -> nie miesci sie w 16-bit offsetie.

Rozwiazanie (historycznie wierne - jak Windows 3.1 SVGA driver):
  Mechanizm "huge selectors": 15 kolejnych selektorow GDT, kazdy 64KB fragment LFB.
  GDI wybiera odpowiedni selektor na podstawie flat_offset / 65536.

  Okna VESA (SEL_VESA_BASE = 0xA0, kazde +8):
    0xA0: base=LFB+0*65536,  limit=65535  (wiersze  0..33)
    0xA8: base=LFB+1*65536,  limit=65535  (wiersze 34..67)
    ...
    0xF0: base=LFB+14*65536, limit=4095   (wiersze 477..479, ostatnie)

  Rysowanie piksela na flat_offset:
    win = flat_offset >> 16;          -> numer okna (0..14)
    off = flat_offset & 0xFFFF;       -> offset w oknie (0..65535)
    sel = SEL_VESA_BASE + win * 8;    -> selektor GDT
    MK_FP(sel, off)[0..2] = B, G, R

  SEL_FONT przesuniety na 0xF8 (za oknami VESA).
  SEL_VESA (0x90) zostaje jako alias okna 0 (kompatybilnosc z pm32_entry).

MAPA GDT (STEP10 - po huge selectors)
--------------------------------------
0x00  null
0x08  SEL_CODE32      flat 32-bit code (base=0, limit=4GB) - PM entry
0x10  SEL_DATA32      flat 32-bit data (base=0, limit=4GB) - font ROM, stos
0x18  SEL_DATASEG     loader DGROUP (base=g_cs_phys, limit=64KB)
0x20  SEL_CODE16      16-bit code (base=g_cs_phys) - powrot do RM, int3f
0x28  SEL_DATA16      16-bit data (base=g_cs_phys) - powrot do RM
0x30  SEL_APP_CODE    16-bit code apki (base=g_app_phys)
0x38  SEL_VGA         VGA text buffer (base=0xB8000, limit=0x09FF)
0x40  SEL_APP_DATA    16-bit data apki (base=g_app_data_phys)
0x48  SEL_DLL_CODE(0) KERNEL code
0x50  SEL_DLL_DATA(0) KERNEL data (DGROUP)
0x58  SEL_DLL_CODE(1) USER code
0x60  SEL_DLL_DATA(1) USER data (DGROUP)
0x68  SEL_DLL_CODE(2) GDI code
0x70  SEL_DLL_DATA(2) GDI data (DGROUP)
0x78  SEL_DLL_CODE(3) (wolny slot)
0x80  SEL_DLL_DATA(3) (wolny slot)
0x88  SEL_THUNK       thunki INT 3F (base=g_thunk_phys, 16-bit code)
0x90  SEL_VESA        alias okna 0 LFB (kompatybilnosc pm32_entry, 32-bit)
0x98  (zarezerwowane - bylo SEL_FONT, usuniete w STEP10)
0xA0  SEL_VESA_WIN(0) LFB okno 0: base=LFB+0*65536,  limit=65535 (wiersze  0-33)
0xA8  SEL_VESA_WIN(1) LFB okno 1: base=LFB+1*65536,  limit=65535 (wiersze 34-67)
0xB0  SEL_VESA_WIN(2) LFB okno 2: base=LFB+2*65536,  limit=65535
0xB8  SEL_VESA_WIN(3) LFB okno 3: base=LFB+3*65536,  limit=65535
0xC0  SEL_VESA_WIN(4) LFB okno 4: base=LFB+4*65536,  limit=65535
0xC8  SEL_VESA_WIN(5) LFB okno 5: base=LFB+5*65536,  limit=65535
0xD0  SEL_VESA_WIN(6) LFB okno 6: base=LFB+6*65536,  limit=65535
0xD8  SEL_VESA_WIN(7) LFB okno 7: base=LFB+7*65536,  limit=65535
0xE0  SEL_VESA_WIN(8) LFB okno 8: base=LFB+8*65536,  limit=65535
0xE8  SEL_VESA_WIN(9) LFB okno 9: base=LFB+9*65536,  limit=65535
0xF0  SEL_VESA_WIN(10)LFB okno 10: base=LFB+10*65536, limit=65535
0xF8  (SEL_VESA_WIN 11-14 gdyby potrzeba; na razie 11 okien pokrywa 720896B > 921600? nie)

Uwaga: 640*480*3 = 921600 B
  okno 0:  B[0..65535]       -> wiersze 0..33  (34 wiersze * 1920 = 65280)
  okno 1:  B[65536..131071]  -> ...
  okno 13: B[851968..917503] -> wiersze 443..477
  okno 14: B[917504..921599] -> wiersze 478..479 (limit=4095)
  Razem: 15 okien (0xA0..0xF0, co 8 = 15*8=120B)

  GDT konczy sie na 0xF0+7 = 0xF7 (248B) + null = 256B total
  SEL_FONT (0xF8): base=g_font_phys, limit=0x0FFF - zaraz za oknami VESA
