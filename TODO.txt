ETAP 10 - Pelna aplikacja Win16 + pelnoekranowy TextOut           [DONE]
--------------------------------------------------------------------------
Cel: "Hello, Win16!" widoczne w dowolnym miejscu ekranu graficznego 640x480.

Problem: TextOut w GDI.EXE ograniczony do y<20 (pierwsze 64KB LFB).
  640*480*3 = 921600 B > 65535 -> nie miesci sie w 16-bit offsetie.

Rozwiazanie (historycznie wierne - jak Windows 3.1 SVGA driver):
  Mechanizm "huge selectors": 15 kolejnych selektorow GDT, kazdy 64KB fragment LFB.
  GDI wybiera odpowiedni selektor na podstawie flat_offset >> 16.

  Okna VESA (SEL_VESA_BASE = 0xA0, kazde +8):
    0xA0: base=LFB+0*65536,  limit=65535  (wiersze  0..33)
    0xA8: base=LFB+1*65536,  limit=65535  (wiersze 34..67)
    ...
    0x110: base=LFB+14*65536, limit=4095  (wiersze 478..479, ostatnie)
  SEL_FONT = 0x118 (zaraz za ostatnim oknem: 0x110 + 8 = 0x118)

  Rysowanie piksela na flat_offset:
    win = flat_offset >> 16;          -> numer okna (0..14)
    off = flat_offset & 0xFFFF;       -> offset w oknie (0..65535)
    sel = SEL_VESA_BASE + win * 8;    -> selektor GDT
    MK_FP(sel, off)[0] = B; [1] = G; [2] = R;

CEL: URUCHOMIENIE SKIFREE (SKI.EXE - oryginalna gra Windows 3.1, 1992)
===========================================================================
SKI.EXE: 88848B, 2 segmenty (CODE 23KB + DATA 3KB), 86 relokacji
  - 65 importow: KERNEL (17 ord), GDI (14 ord), USER (34 ord)
  - 86 zasobow RT_BITMAP (sprite'y gracza, przeszkod, tla)
  - Brak dzwieku (MMSYSTEM nie uzywany)
  - Game loop: PeekMessage (nie GetMessage) -> WM_TIMER/WM_PAINT -> BitBlt

Problem #1: nasze KERNEL/GDI/USER maja INNE numery ordynalow niz prawdziwy
  Win16. Np. nasz KERNEL.1=OutputDebugString, ale SKI chce KERNEL.115.
  Trzeba przebudowac DLL z prawdziwymi Win16 numerami ordynalow.

Problem #2: SKI wymaga funkcji ktorych jeszcze nie mamy:
  InitTask, GlobalAlloc, LocalAlloc, BitBlt, LoadBitmap, PeekMessage,
  GetTickCount, CreateCompatibleDC, SelectObject, GetDeviceCaps, ...

        Implementacja: loader.c init_mouse_ps2() z ps2_wait_write() i ps2_read_byte().
        Sekwencja: 0xD4+0xFF (reset) -> ACK+0xAA+0x00, 0xD4+0xF4 (enable streaming) -> ACK.
        IDT[0x2C] = irq12_handler, loader zeruje KCB bajty 272..290.

        BUG: klawiatura przestawala dzialac gdy mysz wchodzila w okno QEMU.
        Przyczyna: trzy warunki musza byc spelnionia jednoczesnie zeby IRQ12 docieralo do CPU:
          (1) PIC master IRQ2 odblokowany (cascade do slave PIC)
          (2) PIC slave IRQ12 odblokowany
          (3) PS/2 CCB bit1=1 (AUX IRQ enable)
        Bez (1): slave PIC odciety od CPU -> IRQ12 nigdy nie dociera.
        Bez (3): kontroler PS/2 produkuje bajty myszy ale nie generuje przerwania.
        Efekt: bufor PS/2 (1 bajt) zapelniany przez pakiety myszy -> klawiatura nie moze
          wstawic danych -> IRQ1 przestaje strzelic -> keyboard martwy.

        Naprawka PIC master mask: 0xFC -> 0xF8 (odblokowuje IRQ2 cascade do slave).
          0xFC = 11111100b - bit2=1 blokowal IRQ2 (cascade).
          0xF8 = 11111000b - bit0=IRQ0, bit1=IRQ1, bit2=IRQ2/cascade - wszystkie on.

        Naprawka CCB (AUX IRQ enable):
          Dlaczego nie w real mode (loader.c init_mouse_ps2):
            - Wariant read-modify-write (0x64<-0x20, odczyt, 0x64<-0x60, zapis):
              BIOS INT9 (handler IRQ1) zjada bajt odpowiedzi komendy 0x20 zanim nasz
              kod zdazy go odczytac -> ps2_read_byte() czeka w nieskonczonosc.
            - Wariant direct write (0x64<-0x60, 0x60<-0x47) w real mode:
              Mysz jest juz w streaming mode (po 0xF4) -> natychmiast flood IRQ12 ->
              BIOS INT 74h (domyslnie IRET lub niezainicjalizowany) nie obsługuje danych
              -> hang.
          Rozwiazanie: zapis CCB=0x47 w pm_call.asm po konfiguracji PIC+IDT, przed STI.

        Rozwiazanie: wydzielic do rc_loader.c generyczna funkcje:

          static int find_ne_resource(unsigned short type_id, unsigned short res_id,
                                      unsigned long *out_file_off,
                                      unsigned short *out_size);
            Zwraca 1 jesli znaleziony; out_file_off = offset w pliku (bajty),
            out_size = rozmiar w bajtach.
            type_id: 0x8002=RT_BITMAP, 0x8004=RT_MENU, 0x8005=RT_DIALOG,

        Format tablicy zasobow NE (ne_rsrctab):
          rscAlignShift (WORD) - potega 2 dla przeliczania offsetow
          Bloki typow: rscType(WORD) rscCount(WORD) rscProc(DWORD)
            rscType == 0 -> koniec tablicy
            Per zasob: rnOffset(WORD) rnLength(WORD) rnFlags(WORD) rnID(WORD) ...
            Offset w pliku = rnOffset << rscAlignShift
            Rozmiar = rnLength << rscAlignShift
            rnID: bit15=1 -> ID liczbowy (rnID & 0x7FFF); bit15=0 -> offset stringa

        Jezeli zwracamy FALSE -> TM/DM dziala normalnie. Klawiatura Ctrl+A nie wywola
        ID_HELP_ABOUT, ale okno normalnie zamknie sie przez inne mechanizmy.

[x] 19h: DialogBox + EndDialog (minimalny modal dialog stub)
        Win1App/Win16App uzywaja DialogBox dla "About" dialog.
        Bez tego: apka dziala (pomija About), ale nie pokazuje dialogu po Ctrl+A.

        Nowe exporty USER.EXE:
          DialogBox (USER.87): tworzy modal dialog, zwraca kod zakonczenia
          EndDialog (USER.88): ustawia flage konca dialogu, zwraca do DialogBox

        Minimal implementation:
          DialogBox:
            1. Znajdz RT_DIALOG (type=5) w zasobach apki o danym ID
            2. Sparsuj dialog template: x,y,w,h, DlgProc style, tytul, controls
            3. Przydziel HWND dla dialogu (parent ma jego okno zablokowane)
            4. Wywolaj DlgProc(hwnd, WM_INITDIALOG, 0, 0)
            5. Uruchom nested GetMessage loop (dopoki g_dialog_result == -1)
            6. Zniszcz dialog, zwroc g_dialog_result
          EndDialog(hwndDlg, retCode):
            Ustaw g_dialog_result = retCode -> wyjdz z nested loop

        Dialog template format (Win16):
          Naglowek: dtStyle(DWORD) dtItemCount(BYTE) dtX dtY dtCX dtCY (WORD each)
          Tytul: null-terminated string
          Font (jesli DS_SETFONT): pointsize(WORD) + name(string)
          Kontrolki: dla kazdego:
            dtilStyle(DWORD) dtilX dtilY dtilCX dtilCY(WORD) dtilID(WORD)
            dtilClass(string lub atom) dtilText(string) dtilInfo(BYTE)

        Na poczatek: bez rysowania kontrolek - tylko wywolac DlgProc z WM_INITDIALOG
          i czekac na EndDialog. Tworzy widoczny czarny prostokat.
        Pelne rysowanie kontrolek (static text, buttons): osobny podkrok.

[ ] 20f: Prawdziwa ikona z zasobow NE (wymaga ETAP 18 rc_loader.c)
        Format ikony Win16 w NE:
          RT_GROUP_ICON (0x800E): katalog ikon - GRPICONDIR + GRPICONDIRENTRY[]
            GRPICONDIR: idReserved(2) idType(2) idCount(2)
            GRPICONDIRENTRY: bWidth bHeight bColorCount bReserved
                             wPlanes wBitCount dwBytesInRes nId
          RT_ICON (0x8003): surowe dane ikony - BITMAPINFOHEADER + XOR mask + AND mask
            biBitCount: 1 (mono), 4 (16 kolorow), 8 (256 kolorow)
            Rozmiar: 32x32 (standard) lub 16x16 (small)

        Proces wczytania ikony dla pliku EXE:
          1. Otworz plik EXE (DOS INT 21h AH=3Dh) - w real mode przed PM
          2. Znajdz NE header (read MZ stub -> e_lfanew -> seek -> read NE header)
          3. Uzyj rc_loader.find_ne_resource(RT_GROUP_ICON, 1) -> file_off, size
          4. Wczytaj GRPICONDIR, wybierz najlepszy wpis (preferuj 32x32 4bpp)
          5. Uzyj rc_loader.find_ne_resource(RT_ICON, nId) -> ikona danych
          6. Wczytaj dane ikony do bufora shell_icons[i] (max 32x32x4bpp = 512B/ikone)

        Renderowanie ikony 32x32 4bpp:
          Paleta 16 kolorow Win16 (standard VGA): hardcode w shell.c
          XOR mask: piksele (4bpp packed, dwa piksele na bajt)
          AND mask: przezroczystosc (1bpp, 1=transparent)
          Rysowac piksel po pikselu do LFB 24bpp:
            jezeli AND_bit==1: pomiń (tlo przebija)
            jezeli AND_bit==0: uzyj koloru z palety VGA[XOR_nibble]

        Nowy plik: shell_icon.c lub jako czesc rc_loader.c
          render_icon_32(unsigned char far *icon_data, int screen_x, int screen_y);

[ ] 20g: Integracja z loaderem - fdauto.bat bez argumentu = shell
        Zmiana zachowania loadera:
          Aktualnie: loader.exe SKITEST.EXE (argument z linii polecen)
          Po zmianie: loader.exe bez argumentu -> uruchom shell
                      loader.exe NAZWA.EXE    -> uruchom bezposrednio (jak dotychczas)

        Parsowanie argc/argv w loaderze (DOS PSP: [PSP:80h] = dlugosc cmd line):
          Jezeli brak argumentu lub argument = "" -> tryb shell
          Jezeli jest argument -> bezposrednie uruchomienie (kompatybilnosc wsteczna)

        fdauto.bat dla shell mode:
          LOADER.EXE         (bez argumentu -> shell)
        fdauto.bat dla trybu bezposredniego (jak teraz):
          LOADER.EXE SKITEST.EXE

        Nowy plik: shell.c
          Kompilacja: wcc -ml -q shell.c -fo=shell.obj
          Linkowanie: loader.exe = ... shell.obj
          Zawiera: shell_run() wywolywane z loader.c gdy brak argumentu.
