ETAP 7 - INT 3F DLL thunk: przelaczanie DS przy wywolaniach DLL   [DONE]
--------------------------------------------------------------------------
Cel: poprawne przelaczanie DS=DGROUP przy kazym wywolaniu funkcji DLL,
     tak jak w oryginalnym Windows 3.x KERNEL (przez INT 3F).
Mechanizm:
  - Kazdy eksport DLL ma 5-bajtowy thunk: CD 3F, dll_idx, off_lo, off_hi
  - Thunki siedza w osobnym bloku DOS memory z wlasnym selektorem GDT (SEL_THUNK=0x88)
  - IMPORTORDINAL patchuje far call do SEL_THUNK:thunk_off (zamiast surowego offsetu)
  - INT 3F handler w PM (SEL_CODE16, wektor 0x3F w IDT):
      1. Czyta dll_idx i func_off z thunku (przez ES = CS thunku)
      2. Zapisuje do int3f_stack[depth]: DS callera, orig_ret_ip, orig_ret_cs
      3. Patchuje IRET frame: CS=SEL_DLL_CODE(dll_idx), IP=func_off
      4. Patchuje adres powrotu w ramce callera -> int3f_trampoline:SEL_CODE16
      5. Ustawia DS = SEL_DLL_DATA(dll_idx)
      6. IRET -> laduje do funkcji DLL z DS=DGROUP
  - int3f_trampoline (wywolany przez RETF n z funkcji DLL):
      1. Dekrementuje depth, czyta int3f_stack[depth]
      2. Przywraca DS callera
      3. JMP FAR do orig_ret_ip:orig_ret_cs -> powrot do callera
[x] loader.c: alokacja bloku thunkow (_dos_allocmem), emit_thunk(dll_idx, func_off)
    - g_thunk_phys, g_thunk_size jako globale dla pm_call.asm
    - apply_fixups IMPORTORDINAL: patch z SEL_THUNK:thunk_off (nie SEL_DLL_CODE:func_off)
[x] loader.c: alokacja IDT (64 wpisy * 8 B = 512 B), g_idt_phys
    - Wpisy 0x00-0x3E: null descriptor (P=0)
    - Wpis 0x3F: 16-bit interrupt gate -> int3f_handler w SEL_CODE16
[x] pm_call.asm: nowy selektor GDT SEL_THUNK (0x88), patchowany z g_thunk_phys
[x] pm_call.asm: LIDT przed LGDT, idtr_int3f patchowany z g_idt_phys
[x] pm_call.asm: int3f_handler (16-bit PM, w _TEXT):
    - push bp/ax/bx/cx/si/es; czyta thunk przez ES; patchuje IRET frame i ret addr
[x] pm_call.asm: int3f_trampoline + int3f_stack[8] (8 poziomow zagniezdzen)
[x] Weryfikacja: OutputDebugString 3x z poprawnym DS (KERNEL's DGROUP)
    - DS przelaczany przez int3f_handler na SEL_DLL_DATA przed wejsciem do DLL
    - Trampolina przywraca DS callera po powrocie z DLL (znak 'T' na COM1)
    - Wszystkie 3 wywolania OutputDebugString widoczne na COM1
    Klucze techniczne:
    - Przy RETF n CPU: pop IP, pop CS, SP+=n -> thunk czysci argi za nas, nic extra
    - int3f_stack musi byc LIFO (glebokosc 8 = wystarczy dla zagniezdzen DLL->DLL)
    - FLAGS z INT 3F maja IF=0 (CPU wylacza przerwania); IRET przywroci IF
    - IDT base = g_idt_phys (DOS _dos_allocmem, osobny blok od kodu)
    - SS:SEL_DATA16 ma ten sam base co CS:SEL_CODE16 -> SS: override do zapisu w handlerze
    - KERNEL.EXE sam ma 3 IMPORTORDINAL fixupy (ordinals 3,4,113) od wlink windows_dll
      runtime -> ignorujemy (nie sa wywolywane w naszym tescie)
