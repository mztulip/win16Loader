ETAP 10 - Pelna aplikacja Win16 + pelnoekranowy TextOut           [DONE]
--------------------------------------------------------------------------
Cel: "Hello, Win16!" widoczne w dowolnym miejscu ekranu graficznego 640x480.

Problem: TextOut w GDI.EXE ograniczony do y<20 (pierwsze 64KB LFB).
  640*480*3 = 921600 B > 65535 -> nie miesci sie w 16-bit offsetie.

Rozwiazanie (historycznie wierne - jak Windows 3.1 SVGA driver):
  Mechanizm "huge selectors": 15 kolejnych selektorow GDT, kazdy 64KB fragment LFB.
  GDI wybiera odpowiedni selektor na podstawie flat_offset >> 16.

  Okna VESA (SEL_VESA_BASE = 0xA0, kazde +8):
    0xA0: base=LFB+0*65536,  limit=65535  (wiersze  0..33)
    0xA8: base=LFB+1*65536,  limit=65535  (wiersze 34..67)
    ...
    0x110: base=LFB+14*65536, limit=4095  (wiersze 478..479, ostatnie)
  SEL_FONT = 0x118 (zaraz za ostatnim oknem: 0x110 + 8 = 0x118)

  Rysowanie piksela na flat_offset:
    win = flat_offset >> 16;          -> numer okna (0..14)
    off = flat_offset & 0xFFFF;       -> offset w oknie (0..65535)
    sel = SEL_VESA_BASE + win * 8;    -> selektor GDT
    MK_FP(sel, off)[0] = B; [1] = G; [2] = R;

CEL: URUCHOMIENIE SKIFREE (SKI.EXE - oryginalna gra Windows 3.1, 1992)
===========================================================================
SKI.EXE: 88848B, 2 segmenty (CODE 23KB + DATA 3KB), 86 relokacji
  - 65 importow: KERNEL (17 ord), GDI (14 ord), USER (34 ord)
  - 86 zasobow RT_BITMAP (sprite'y gracza, przeszkod, tla)
  - Brak dzwieku (MMSYSTEM nie uzywany)
  - Game loop: PeekMessage (nie GetMessage) -> WM_TIMER/WM_PAINT -> BitBlt

Problem #1: nasze KERNEL/GDI/USER maja INNE numery ordynalow niz prawdziwy
  Win16. Np. nasz KERNEL.1=OutputDebugString, ale SKI chce KERNEL.115.
  Trzeba przebudowac DLL z prawdziwymi Win16 numerami ordynalow.

Problem #2: SKI wymaga funkcji ktorych jeszcze nie mamy:
  InitTask, GlobalAlloc, LocalAlloc, BitBlt, LoadBitmap, PeekMessage,
  GetTickCount, CreateCompatibleDC, SelectObject, GetDeviceCaps, ...
